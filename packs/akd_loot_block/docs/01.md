# 宝物ブロックアドオン - ランダムに金ブロックを発生させる

[1つ上へ](./index.md)

## やること

ワールドのランダムな草ブロックを金ブロックに置換する。

## 使う仕組み

ワールド生成に対し、「feature」という仕組みで干渉することができる。

- `minecraft:single_block_feature`はブロック1つを置換する。
- `may_replace` を指定すると、そのブロックの場合にだけ置換する。

## 手順

### フォルダ構成

```text
Behavior Pack
├─ manifest.json
├─ features
│  └─ lucky_block_surface.json
└─ feature_rules
   └─ lucky_block_surface_rule.json
```

### lucky_block_surface.jsonを作成

```json
{
  "format_version": "1.26.40",
  "minecraft:single_block_feature": {
    "description": {
      "identifier": "akd_lucky_block:lucky_block_surface"
    },
    "places_block": "minecraft:gold_block",
    "may_replace": [
      "minecraft:grass_block",
      "minecraft:sand",
      "minecraft:stone",
      "minecraft:dirt"
    ],
    "enforce_placement_rules": false,
    "enforce_survivability_rules": false
  }
}
```

minecraft:gold_blockは後でお宝ブロックに変更する。

### lucky_block_surface_rule.jsonを作成


```json
{
  "format_version": "1.26.40",
  "minecraft:feature_rules": {
    "description": {
      "identifier": "akd_lucky_block:lucky_block_surface_rule",
      "places_feature": "akd_lucky_block:lucky_block_surface"
    },

    "conditions": {
      "placement_pass": "after_surface_pass",

      "minecraft:biome_filter": [
        {
          "test": "has_biome_tag",
          "operator": "==",
          "value": "overworld"
        }
      ]
    },

    "distribution": {
      "iterations": 4,

      "scatter_chance": {
        "numerator": 1,
        "denominator": 16
      },

      "coordinate_eval_order": "xzy",

      "x": {
        "distribution": "uniform",
        "extent": [0, 15]
      },

      "z": {
        "distribution": "uniform",
        "extent": [0, 15]
      },

      "y": "query.heightmap(variable.worldx, variable.worldz) - 1"
    }
  }
}
```

### 解説

```

"iterations": 4,

"scatter_chance": {
    "numerator": 1,
    "denominator": 16
},

```

は、置き換えの頻度。

scatter_chanceは、この割合のチャンクで試行を試みるということ。numerator/denominator。

iterationsは選択されたチャンクあたりの試行回数。

つまり、上の例では、16チャンクに1つ、最大2個まで生成されるチャンクがあるということ。

1/1（100%）を指定したい場合は、scatter_chanceごと削除しないとエラーになる。

> "distribution": "uniform",

は、チャンク内の0～15を均等に置換する。

> "y": "query.heightmap(variable.worldx, variable.worldz) - 1"

は、高さマップ。そこから-1することで地表のブロックを置換する。


## ChatGPTの回答メモ

できます。しかもこの用途なら、**Script APIは不要**で、Behavior Packのワールド生成機能だけでかなりきれいに実現できます。

構成はかなり単純で、

```text
Behavior Pack
├─ manifest.json
├─ features
│  └─ rare_gold_surface.json
└─ feature_rules
   └─ rare_gold_surface_rule.json
```

の2ファイルを追加するイメージです。

### 1. 「草ブロックを金ブロックに置換するFeature」

`features/rare_gold_surface.json`

```json
{
  "format_version": "1.21.40",
  "minecraft:single_block_feature": {
    "description": {
      "identifier": "myaddon:rare_gold_surface"
    },
    "places_block": "minecraft:gold_block",
    "may_replace": [
      "minecraft:grass_block"
    ]
  }
}
```

`minecraft:single_block_feature` はその名の通り1ブロックだけ配置するFeatureです。`may_replace` を指定すると、そのブロックの場合にだけ置換できます。したがってここでは**草ブロックだった場合だけ金ブロックに変わる**ことになります。([GitHub][1])

現在のBedrockでは草ブロックのIDは `minecraft:grass_block` で問題ありません。([Microsoft Learn][2])

### 2. 「どこに・どのくらいの頻度で発生するか」を決める

`feature_rules/rare_gold_surface_rule.json`

```json
{
  "format_version": "1.21.40",
  "minecraft:feature_rules": {
    "description": {
      "identifier": "myaddon:rare_gold_surface_rule",
      "places_feature": "myaddon:rare_gold_surface"
    },

    "conditions": {
      "placement_pass": "after_surface_pass",

      "minecraft:biome_filter": [
        {
          "test": "has_biome_tag",
          "operator": "==",
          "value": "overworld"
        }
      ]
    },

    "distribution": {
      "iterations": 1,

      "scatter_chance": {
        "numerator": 1,
        "denominator": 10
      },

      "coordinate_eval_order": "xzy",

      "x": {
        "distribution": "uniform",
        "extent": [0, 15]
      },

      "z": {
        "distribution": "uniform",
        "extent": [0, 15]
      },

      "y": "query.heightmap(variable.worldx, variable.worldz) - 1"
    }
  }
}
```

Feature Ruleはチャンク単位でワールド生成Featureを配置できます。`iterations: 1` なので各チャンクにつき候補地点は1か所、`scatter_chance` を `1/10` にすることで、その試行自体が**平均10チャンクに1回**だけ発生します。公式仕様でも `scatter_chance` はFeatureの散布そのものが発生する確率です。([Microsoft Learn][3])

X/Zについては、

```json
"extent": [0, 15]
```

なので、16×16ブロックのチャンク内からランダムに1座標を選びます。

そして重要なのが、

```json
"y": "query.heightmap(variable.worldx, variable.worldz) - 1"
```

です。

公式例では `query.heightmap(...)` を使って「地表のすぐ上」にキノコなどを置いています。([Microsoft Learn][4]) したがって今回はそこから1ブロック下げて、**地表そのもの**を対象にします。

その場所が

```text
草ブロック
```

なら

```text
↓
金ブロック
```

となります。

砂、石、雪、泥などだった場合は `may_replace` に引っかからないので、何も起こりません。

---

つまり処理を擬似コードで書くと、ほぼこうです。

```text
各Overworldチャンクについて

    10%の確率で
        X = 0～15からランダム
        Z = 0～15からランダム

        そのX,Zの地表を調べる

        if 地表 == 草ブロック:
            草ブロック → 金ブロック
```

これならかなり狙い通りです。

ただし「**10チャンクにつき必ず平均1個の金ブロック**」とは少し違います。たとえば砂漠チャンクで抽選に当たっても、選ばれた場所は砂なので失敗します。そのためOverworld全体で数えると実際の金ブロック密度は **1/10チャンクより少なく**なります。

「草原や森林など、草ブロックが地表にある地域について、おおむね10チャンクに1個」であれば上記で十分自然です。

むしろこの仕様だと、

> 草原をかなり探索していると、ものすごく稀に地面に金ブロックが埋まっている

というMinecraftらしい生成になります。Featureはワールド生成時に生成されるため、**既に生成済みのチャンクには後から金ブロックは出現せず、新しく生成するチャンクでのみ反映される**点にも注意してください。ワールド生成FeatureはBehavior Packの `features` と `feature_rules` で制御するのが現在の正式な仕組みです。([Microsoft Learn][5])

なお、この程度なら `scatter_feature` をさらに挟む必要はありません。**Feature Rule自身に散布確率・X/Z・高さを直接書けるので、`single_block_feature + feature_rules` の2段だけで十分**です。
